# Security

What Shelf-to-Shop does to protect sellers, their customers and the platform, mapped to OWASP ASVS 5.0
Level 2 where it applies, and what is not done yet. Every "done" line names where to look; every gap is
listed under "Not done yet" rather than left out.

## Threats we design for

- A stranger using the public shop page to spam a seller's order book or WhatsApp, or to read another
  shop's private data.
- One seller reaching another seller's items, videos, orders or photos.
- A video, photo or price tag that tries to steer the AI ("ignore your instructions"), or a file that
  is not what it claims to be.
- The server being used to fetch arbitrary URLs (SSRF).
- Secrets leaking into the repo, logs or responses; a vulnerable dependency.

## Controls

| Area (ASVS chapter) | What is in place | Where |
|---|---|---|
| Sessions (V7) | Random 32-byte tokens, stored only as an HMAC with the server secret; HttpOnly, SameSite=Lax cookies, `Secure` in demo and production; 14-day expiry; sign-out revokes the session row | `shelf/auth/sessions.py` |
| CSRF (V3/V7) | Double-submit token on every state-changing request (header must match the session's token) | `current_seller` |
| Commit before reply | A request's writes are committed before the response is sent (a fast client never sees stale data) | `api/deps.py`, test `test_writes_are_committed_before_the_response_is_sent` |
| Access control (V8) | Every seller query filters on the signed-in seller's workspace; other shops' ids answer 404 | `api/v1/*`, tests `test_other_workspaces_see_nothing`, `test_new_endpoints_are_scoped_to_the_workspace`, `test_uploads_belong_to_one_shop` |
| Public data (V8) | The shop page serves an allowlisted snapshot: no internal ids, emails, evidence, videos or costs; the sample shop template is never public | `catalog/publish.py`, test asserts private fields are absent |
| Input validation (V2/V5) | Pydantic models with bounds on every body; prices 1 to 1 crore; text lengths capped; customer names and notes stripped of links and control characters before they reach WhatsApp | models in `api/v1/*`, `public._clean` |
| Orders | Basket prices come from the published shop, never from the browser; sold-out or removed items are refused; numbers are unique per shop | `public.place_order`, tests |
| File uploads (V5) | Size limits (video 200 MB, photo 12 MB); content sniffed by magic bytes, not name or type; videos checked by ffprobe (duration, resolution, streams) and re-encoded; photos decoded by Pillow, pixel-count capped, re-encoded as JPEG without EXIF or location | `engine/media/probe.py`, `engine/pipeline/photos.py` |
| Storage paths (V5) | Storage keys are generated by the server (random ids) and validated against a strict pattern; no user-supplied paths; public media routes check slug and file name patterns | `shelf/storage.py`, `api/v1/public.py` |
| Media tools | ffmpeg and ffprobe run with argument lists (no shell), file and pipe protocols only, timeouts, and CPU, memory and file-size limits on Linux, with a minimal environment | `engine/media/ffmpeg.py` |
| SSRF (V13) | Outbound HTTP only through an allowlist transport (Meta Model API, Baseten); Open Food Facts uses three fixed hosts, and the server builds every URL from a barcode; image URLs from its answers are checked for host and path before use | `engine/net.py`, `catalog/openfoodfacts.py` |
| Rate limits (V2) | Public orders 10 per 10 minutes per address and 120 per hour per shop; page counters 120 per minute; demo sign-in 20 per 10 minutes; uploads 30 per hour and photo changes 120 per hour per shop | `core/ratelimit.py`, test `test_public_orders_are_rate_limited` |
| HTTP headers (V3) | CSP without `unsafe-inline` (`default-src 'self'`, images also from `images.openfoodfacts.org`), HSTS, `nosniff`, Referrer-Policy, Permissions-Policy (camera and microphone for our own origin only), COOP, `frame-ancestors 'none'`; strict CORS allowlist | `deploy/Caddyfile`, `shelf/main.py` |
| Errors (V16) | Problem+JSON with a stable code and a plain message; no stack traces; every response carries a request id | `core/errors.py`, `core/request_id.py` |
| Logging (V16) | Structured JSON logs; a scrubber removes keys, tokens, emails and phone numbers; audit events for sign-in, sign-out, consent, publishing, photo replacement, bulk edits, profile changes, data export and shop deletion (no personal data in them) | `core/logging.py`, `audit_events` table |
| Configuration | Production refuses demo sign-in, fake AI providers, a non-https site address and a weak secret | `shelf/config.py` |
| AI inputs (prompt injection) | Text, audio and images from videos are passed as data inside clearly marked untrusted blocks; every answer must match a strict JSON schema (one repair retry, then it fails); the models have no tools: they cannot publish, pay or message anyone; publishing always needs the seller's tap | `engine/agents/structured.py` |
| AI provider | Contributor model variants (which may train on content) are refused by configuration; requests use `store: false`; uploaded files expire after an hour and are deleted after use; spend is capped per job, per shop per day and for the whole service per day (totals shared in the database, checked with one guarded update) | `engine/config.py`, `providers/meta_client.py`, `engine/spend.py`, `shelf/jobs/spend.py` |
| Secrets (V13) | Only from environment variables (AWS Parameter Store in production); `.env` is git-ignored; gitleaks runs before every commit and over the full history in CI, with extra rules for Meta and our own keys | `.pre-commit-config.yaml`, `.gitleaks.toml`, CI |
| Supply chain (V15) | `uv.lock` and `package-lock.json` pinned; GitHub Actions pinned by commit; Dependabot for Python, npm and Actions; CI fails on pip-audit findings, `npm audit` high-severity findings and any Semgrep finding (python, typescript, react, secrets rule packs) | `.github/workflows/ci.yml`, `.github/dependabot.yml` |
| Infrastructure | One EC2 machine: only ports 80 and 443 open, no SSH (Session Manager), IMDSv2 required, encrypted disk, a role that can read only `/shelf-to-shop/*` parameters | `deploy/cloudformation.yml` |

## Not done yet

- **Sign-in is demo sign-in only** (flag-gated, refused in production). Email one-time codes, refresh
  token rotation and listing or ending other sessions are planned after the hackathon.
- Rate limits live in memory in one API process: right for the single-server deployment, not for
  several servers (would move to Redis or Postgres).
- Page-view counters can be inflated by a script within the rate limit; they are totals only.
- Uploaded files are not virus-scanned; videos and photos are always decoded and re-encoded before use.
- Photos are on the server's disk; moving published photos to Cloudflare R2 with signed URLs is planned.
- C2PA content credentials are not added (they need a certificate from a CA on the C2PA trust list); AI
  backgrounds are labelled in XMP metadata and on the page instead.

## Reporting a problem

Open a private security advisory on the GitHub repository rather than a public issue.
